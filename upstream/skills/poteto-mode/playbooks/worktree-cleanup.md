### Worktree and simulator cleanup

1. Snapshot and audit. Record the repo drive's free space with `Get-PSDrive <letter>`, then run `& (Join-Path (Split-Path (Split-Path (Get-Command git).Source)) 'bin\bash.exe') <root>/upstream/skills/poteto-mode/scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` through `shell`, never plain `bash` (principle-build-the-lever). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `~/.mixdog/data/worktrees-v1/<id>/x` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, and PR state, then suggests a bucket. It reads no conversations, so its `safe` bucket says nothing about whether a chat still uses the tree.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user or sidebar and cross-check every candidate. Treat every candidate as possibly in use until the checks in step 3 and the user's pinned set clear it. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every candidate, run `session` `list` with `include_agents: true` and take the sessions whose `cwd` is the worktree or inside it. One that is `working` or recently used by its `lastUsedAt` holds the tree. Then query the `recall` tool yourself, loaded through `load_tool`, with the worktree's path and branch, for chats that worked on it from another folder. When an entry leaves unclear whether that chat still uses the tree, read just those items with `session` `read` on its session id. When `recall` is unavailable or reports that memory is off, stop before any removal and ask the user to turn on memory in Mixdog's settings, then run this playbook again. A pinned chat spawns arena and repro trees into sibling worktrees via background subagents, and those are in use even when their names never hit the sidebar.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is N untracked files, which can be the user's work. Show them and get a decision, as for `wip`. Per Autonomy, clean and merged and not-in-use proceeds. `wip`, `scratch`, and in-use pause.
5. Prune the confirmed set. Per path, run `git worktree remove <path>` through the `git` tool, which maps it to its managed removal. Report a refused removal instead of forcing it. If the dir survives on ignored build artifacts, remove it with `Remove-Item -Recurse -Force <path>`, then run `git worktree prune` through the `git` tool. Branch refs survive, so no commits are lost. Confirm with `Get-PSDrive <letter>` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. Without `xcrun`, write `Skipped in Mixdog: simulators. xcrun is not installed.` More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** free space before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted or untracked work).
